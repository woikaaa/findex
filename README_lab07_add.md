# Лаба 7: пошук у вебі (FastAPI)

**Мета.** Дати пошуку HTTP API, сторінку з полем запиту і публічну адресу.

## Запуск

```bash
pip install -e .
findex index demo/corpus -o demo/index.bin     # індекс демо-корпусу (його ж кладемо в образ)
findex serve --port 8000                       # сторінка: http://127.0.0.1:8000, API: /api/docs
findex serve --workers 4                       # чотири процеси
```

Налаштування читаються зі змінних оточення (`pydantic-settings`): `INDEX_PATH`, `CORPUS_PATH`,
`LOG_LEVEL`, `PORT`. Аргументи `findex serve --index/--corpus/--port` просто кладуть їх у ці змінні.

## Маршрути

| Маршрут | Що робить |
|---|---|
| `GET /search?q=&k=&scorer=&page=` | пошук; `k` це розмір сторінки (1–50), `scorer` це `bm25` або `tfidf`, `page` від 1; поганий параметр дає 422 |
| `GET /docs/{doc_id}` | документ; невідомий дає 404 |
| `GET /stats` | розмір індексу, спосіб зберігання, час роботи |
| `GET /health` | 200, коли індекс завантажений; 503, поки ні (на це дивиться платформа) |
| `GET /` | сторінка Jinja2: поле пошуку, уривки з підсвіткою, бали, сторінки результатів |
| `GET /view/{doc_id}` | перегляд документа на сторінці |

## Як це влаштовано

- `lifespan` один раз завантажує індекс (у фоні, щоб `/health` чесно відповідав 503, поки йде
  завантаження) і кладе його в `app.state`. Маршрути отримують його через `Depends`.
- Pydantic стоїть лише на вході (`SearchParams`) і виході (`SearchResponse`, `DocResponse`, ...).
  Всередині лишаються dataclass-и з лаб 2–3: `Index`, `Searcher`, `HitData`.
- Кожен запит має id (`X-Request-ID`, свій або створений). Він є в кожному рядку логу. Якщо
  стається несподіваний виняток, у лог іде стек разом з id, а клієнт бачить лише
  `{"detail": "Внутрішня помилка сервера", "request_id": "..."}` з кодом 500.
- Тести (`tests/test_web.py`) не потребують файлу індексу: `dependency_overrides` підставляє
  маленький індекс з `conftest`. Є успішний пошук, 422, 404, `/health` → 503, 500 з id.

## `def` чи `async def`

Пошук це чистий Python на процесорі. Якщо написати `async def`, ця робота йде прямо в циклі подій
і поки вона триває, цикл не обслуговує нікого іншого. Звичайний `def` FastAPI запускає в пулі
потоків, тож цикл вільний. Перевірка: `uv run python bench_web.py --rounds 8` піднімає справжній
uvicorn і шле 20 одночасних запитів на два маршрути з тією самою роботою, а посеред них один
легкий `/ping`, який нічого не рахує.

<!-- ЗАПОВНИТИ СВОЇМИ ЦИФРАМИ з виводу bench_web.py -->

| Варіант | усі 20 запитів, мс | p50 пошуку, мс | `/ping` медіана, мс | `/ping` макс., мс |
|---|---|---|---|---|
| `def` | ... | ... | ... | ... |
| `async def` | ... | ... | ... | ... |

У коді лишився `def` для всього, де є розрахунок (`/search`, `/docs`, `/stats`, `/`).
`async def` лише в `/health`, де нічого не рахується. Причина в таблиці вище: ... (1–2 речення за моїми цифрами).

## Навантаження (oha)

Команда на один запуск: `oha -z 20s -c 20 "http://127.0.0.1:8000/search?q=україна"`
(20 одночасних з'єднань, 20 секунд). Те саме на розгорнутому сервісі.

<!-- ЗАПОВНИТИ -->

| Що міряю | запитів/с | p50, мс | p95, мс | p99, мс |
|---|---|---|---|---|
| 1 воркер, `async def` | ... | ... | ... | ... |
| 1 воркер, `def` | ... | ... | ... | ... |
| 4 воркери (`--workers 4`) | ... | ... | ... | ... |
| розгорнутий сервіс (Render) | ... | ... | ... | ... |

Що з цього видно (3–5 речень своїми словами, на основі таблиці): GIL (лаба 5) не дозволяє двом
потокам рахувати Python одночасно, тому `def` у пулі потоків дає живий цикл подій, але не дає
більше запитів за секунду; кілька процесів (лаба 5, `ProcessPool`) дають справжнє прискорення,
бо в кожного свій GIL; `asyncio` (лаба 6) допомагає там, де чекаємо мережу, а пошук нічого не чекає.

## Docker

```bash
docker build -t findex .
docker run --rm -p 8000:8000 -e INDEX_PATH=/app/demo/index.bin findex
```

`Dockerfile` двоетапний: у першому `uv sync --locked` ставить залежності за `uv.lock` і сам пакет
(`--no-editable`), у другому лишається тільки `.venv` і демо-дані. Процес працює від користувача
`findex`, не від root. Образ перевіряє себе через `/health`.

## Розгортання (Render)

Сервіс описаний у `render.yaml`: `runtime: docker`, `healthCheckPath: /health`, уся конфігурація
в змінних оточення (`INDEX_PATH`, `CORPUS_PATH`, `LOG_LEVEL`), порт Render дає сам через `PORT`.
Логи видно в панелі Render (вкладка Logs): кожен рядок має id запиту.
